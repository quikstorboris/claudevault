# Next.js 16's dev server blocks cross-origin requests by default -- needs allowedDevOrigins for E2E tests on a non-default port

Running `next dev` on a port other than its usual default (e.g. a dedicated E2E test port like 127.0.0.1:3100, chosen so it never collides with a developer's own `npm run dev` on 3000) triggers Next.js 16's built-in dev-origin safety check: cross-origin access to dev resources is blocked by default, with a console warning naming the exact config needed. Fix is a dev-only config addition:

```ts
// next.config.ts
const nextConfig: NextConfig = {
  allowedDevOrigins: ["127.0.0.1"], // or whatever host the test runner uses
};
```

This setting only affects `next dev`; it has no effect on `next build`/`next start`, so it's safe to leave in permanently rather than needing to be conditionally applied only during test runs.

Why this generalizes: any Next.js 16 project running Playwright (or similar) E2E tests against a `next dev` server on a non-default host/port hits this identically -- it's a framework-level default, not something specific to one app's configuration.

## How this is known

Reproduced directly in unitprep-ui: Playwright running next dev on 127.0.0.1:3100 logged the exact "Cross-origin access... blocked by default" warning; adding allowedDevOrigins: ["127.0.0.1"] to next.config.ts made the warning disappear and the app load correctly.
