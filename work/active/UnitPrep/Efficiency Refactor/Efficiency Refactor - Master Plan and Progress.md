## Chunk specifications

### Phase A

#### A1 - Session `last_seen_at` throttle + merged `set_config` (items 1, 2) [M]
**Problem.** `auth.resolve_session()` (migration `20261002180000_add_user_permission_grants.up.sql:93-127`, `LANGUAGE sql`, `SECURITY DEFINER`) is one `UPDATE auth.sessions SET last_seen_at = now() ... RETURNING`, so every authenticated request takes a row lock and writes WAL. `begin_rls_transaction` (`src/auth/authenticated_user.rs:~416-433`, 195 call sites in ~50 files) does `BEGIN` + two separate `SELECT set_config(...)`. Fixed overhead today: resolve 1 + BEGIN 1 + set_config 2 + COMMIT 1 (+ inline audit insert on writes).
**Do.**
1. New migration (with a real `.down.sql`) replacing `auth.resolve_session` with the same signature and return columns, using the CTE design in the Decisions note ("last_seen_at throttle design"): a read-only `live` CTE with all validity checks, plus a data-modifying `bump` CTE that updates only when `last_seen_at < now() - LEAST(60s, idle_minutes*6s)`. `CREATE OR REPLACE` keeps the `app_service` EXECUTE grant (verify).
2. Merge the two settings into ONE statement: `SELECT set_config('app.current_user_id',$1,true), set_config('app.current_user_roles',$2,true)` in `begin_rls_transaction`; leave `begin_owner_rls_transaction` (BEGIN + 1 set_config) alone.
3. Update docs that say "bump on every request": `AUTHENTICATION.md` (~92-104), `THREAT_MODEL.md` (~88), docstrings in `authenticated_user.rs` (~11-14, 104-110, 432-436).
4. Add `#[ignore]` real-DB tests: two `resolve_session` calls within T leave `last_seen_at` unchanged on the 2nd; an idle session stays rejected; a revoked/deactivated session is rejected; returned columns unchanged. Rerun the existing `query_sessions_own_sql_is_valid_against_the_real_schema` (~`authenticated_user.rs:560`).
**Acceptance.** Idle-timeout semantics unchanged except stored `last_seen_at` may lag by <= T (fails SAFE: session can expire up to T early, never late). Revocation still instant. All gate tests green. Measure requests/sec or p50 on a simple authenticated GET before/after.
**Risk.** Low. Note the tiny snapshot-read window vs. the old row-lock re-check (millisecond, no wider than the existing resolve-to-handler gap). Do not cache the idle env var in a `OnceLock` unless no test mutates `SESSION_IDLE_TIMEOUT_MINUTES` (grep first; optional).
**Explicitly NOT in scope:** any in-memory session cache (see Decisions).

#### A2 - HTTP client policy (item 3) [M]
**Problem.** `src/dropbox/client.rs:133` and `src/process_street/client.rs:128` use `reqwest::Client::new()` (no timeout; verified by two reviewers). `DropboxClient::access_token` (`dropbox/client.rs:150-151`) holds a `tokio::Mutex` across the OAuth refresh HTTP call, so a hung refresh stalls every Dropbox call. `process_street/client.rs:145` logs the full response body at error level (PII risk). PS 429/5xx and an expired Dropbox 401 are hard errors with no retry. ClickUp builds a fresh client per call (`src/api/clickup_connection.rs:54-60` -> `clickup/client.rs:170-178`; it does set a 15 s timeout).
