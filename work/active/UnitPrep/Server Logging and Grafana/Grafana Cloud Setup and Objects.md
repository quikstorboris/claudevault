## The dashboard "UnitPrep API Logs"

- uid `unitprep-api-logs`; URL `https://joyfulpelican1551.grafana.net/d/unitprep-api-logs/unitprep-api-logs`; time `now-6h`, refresh 1m.
- **Source of truth in the repo**: `unitprep-api/dev-tools/grafana/unitprep-api-logs.dashboard.json` (so it can be re-imported into a prod stack). It was generated by a small Python script for the later panels; edit the JSON, then re-import.
- **Versions built this session**: v1 (6 panels) -> v2 (15) -> v3 (17, with the two ClickUp panels from the ClickUp logging session). The api 1.9.131 release (Part 2) then added an Environment picker and a "Tools and people" section; see that note for the current panel list.
- v3 panels (all Loki datasource `grafanacloud-logs`):
  1. Errors (selected range): `sum(count_over_time({job="unitprep-api", level="ERROR"}[$__range]))` (stat, red at 1)
  2. Panics (selected range): same with `|= "panicked"`
  3. Log lines by level: `sum by (level) (count_over_time({job="unitprep-api"}[$__interval]))` (bars)
  4. Requests by status code: `... |= "request completed" | json` by `fields_status`
  5. Request latency, max (ms): `max(max_over_time(... | json | unwrap fields_latency_ms [$__interval]))`
  6. Slowest routes, average ms (table, instant): `topk(10, avg by (route) (avg_over_time(... | label_format route=... | unwrap fields_latency_ms [$__range])))`
  7. p95 latency by route (ms): `topk(8, quantile_over_time(0.95, ... | unwrap fields_latency_ms [$__interval]) by (route))`
  8. 5xx responses by route: `... | json | fields_status >= 500 | label_format route=...`
  9. Database connection errors: `|= "error communicating with database"`
  10. Process Street calls by HTTP status (`|= "Process Street call"`), 11. Process Street rate limits and failures (`rate limit reached` / `request failed`), 12. Dropbox activity (`dropbox (download|upload) succeeded` vs ERROR with target `unitprep::dropbox.*`)
  13. Errors and warnings by module: `sum by (target) (... level=~"ERROR|WARN" | json ...)`
  14. Slow SQL statements (sqlx warnings): `| json | target=~"sqlx.*"`
  15. ClickUp calls by HTTP status, 16. ClickUp rate limits, failures and copy jobs, 17. Errors and warnings (log panel, `level=~"ERROR|WARN" | json`)
- The **route** label is built with `label_format route=<backtick>{{ .span_method }} {{ regexReplaceAll "<uuid regex>|[0-9]{2,}" .span_path ":id" }}<backtick>` so `/clients/<uuid>` and `/clients/<number>` group as one route (`GET /clients/:id`).
- **How it was imported** (it matters for next time): Grafana's import page (`/dashboard/import`) has a plain textarea. The Chrome tool `form_input` **parses JSON-looking strings into objects** (it put `[object Object]` in the box) and `file_upload` only accepts files the session may read (the scratchpad was refused), so the JSON was set through the page's own JavaScript using the native `HTMLTextAreaElement` value setter plus an `input` event, then Load -> **Import (Overwrite)** (same uid replaces the earlier version). Backticks inside a JS template literal break it: build them with `String.fromCharCode(96)` or embed the JSON in a single-quoted string with backslashes and `'` escaped.
- Verified rendering with real data: "Errors: 4" red after the 13:27 DB errors, status codes 200/404/500, max latency, slowest-routes table (e.g. `GET /health/db` 433 ms), 5xx by route (`GET /health/whoami`, `POST /auth/login/begin`), DB-connection errors, errors by module (`sqlx_core::pool::connection`, `sqlx_core::pool::inner`, `unitprep::api::auth_login`, `unitprep::auth::authenticated_user`). Process Street, Dropbox and ClickUp panels were "No data" because those integrations had not run since logging began.

## Grafana UI facts learned (useful for next time)

- **New alert rule prefill**: `/alerting/new/alerting?defaults=<url-encoded JSON>` accepts name, type `grafana-managed`, `queries` (datasource uid, `relativeTimeRange`, `model.expr`, `queryType: instant`), `condition`, `noDataState`, `execErrState` and `annotations` (list of `{key, value}`). This avoids typing into the Monaco query editor, whose auto-closing quotes/braces corrupt typed text. Folder, evaluation group, pending period and contact point still have to be chosen in the form.
- Form clicking is racy: dropdown options render after the click, so a click-then-click batch can miss; screenshot between steps. Editing an existing rule's query was avoided by delete-and-recreate.
- Contact point edit URL uses a base64 id (`email-boris` -> `ZW1haWwtYm9yaXM`); a URL with the plain name gives "Receiver not found". Find the Edit link on `/alerting/notifications`.
- Explore Loki URL pattern: `/explore?schemaVersion=1&panes=<json>` with `datasource: "grafanacloud-logs"`. Drilldown Logs: `/a/grafana-lokiexplore-app/explore/service/unitprep-api/logs?from=now-1h&to=now`.
- **Drilldown and Explore are snapshots, not live**: a page opened earlier keeps showing its old result until refreshed. Boris saw "the last record is 20:07:15Z" because his tab predated the restart; a fresh load showed records through 13:18. Use the refresh button, an auto-refresh interval, or Explore's Live.
- The alert list page can show a rule's contact point blank for a moment right after saving; reload.
- Delete rule dialog says the rule is recoverable from the "Recently deleted" tab by an admin.
