# 

Fixed a runtime bug on Admin > Security Policies (`GET/POST /admin/security-policies` config endpoints): `auth.auth_configuration.step_up_actions` is a `JSONB` column (per migration 20260721194643), but `src/api/auth_configuration.rs` was reading/writing it as plain `Vec<String>` via sqlx, which decodes/encodes as Postgres `TEXT[]`. That type mismatch made every read of the security-policies page fail with "mismatched types; Rust type Vec<String> (as SQL type TEXT[]) is not compatible with SQL type JSONB", surfaced to the admin as a 500. Fixed by wrapping the field as `sqlx::types::Json<Vec<String>>` on both the `get_configuration` read (query_as) and `update_configuration`'s prior-value read (query_scalar) and the UPDATE bind (`sqlx::types::Json(&request.step_up_actions)`), unwrapping `.0` where a plain `Vec<String>` is needed downstream. `cargo check`/`cargo build --release` pass. Rebuilt and restarted the local dev server (was running as a bare `target/release/unitprep` process in a VS Code integrated terminal, not under any supervisor). Could not do a full live-browser E2E check since the admin page requires a real passkey ceremony (Windows Hello) I can't perform headlessly — user should reload the page themselves to confirm the fix.
