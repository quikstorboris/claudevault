# 

Shipped the core matching logic for QMS Template Tagging Assistant Phase 2, per the scope locked this session. New workspace crate unitprep-template-tagger (pure domain logic, no I/O, matching the unitprep-dedup/unitprep-unit-group convention): detect_candidates(document_text, &[TagValue]) -> Vec<Candidate>, a word-bounded, ASCII-case-insensitive literal-value matcher. Deliberately has no notion of QMS document context at all -- the caller is responsible for only ever passing unambiguous tag values (name/address/phone/email/DL#/unit number), per the locked scope decision. Uses to_ascii_lowercase (not to_lowercase) for case-folding specifically so byte offsets stay valid against the original text -- full Unicode case-folding can change a string's byte length and would silently break offset correctness; documented and tested as an explicit limitation (non-ASCII letters like e/E don't fold). 10 unit tests covering case-insensitivity, word-boundary rejection (a value must not match as a substring of a longer token), multiple occurrences, blank-value skipping, absent-value handling, and deliberate non-deduplication across overlapping TagValues (propose-never-modify means the human reviewer dedupes, not this crate). cargo fmt/clippy/test all clean, full workspace build unaffected. Not yet wired to any HTTP endpoint, UI, or .docx parsing -- that's explicitly out of scope for this pass; the crate is pure text-in/candidates-out today.
