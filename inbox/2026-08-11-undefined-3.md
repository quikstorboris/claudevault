# 

Built docx-surgeon, a new standalone workspace crate implementing surgical minimal-diff .docx text editing -- the write-side counterpart to unitprep-template-tagger's detect_candidates, and explicitly built with an eye toward a possible future open-source contribution per Boris's interest (FOSS fan, wants to vet it first before considering publishing). Design: never deserializes the whole document into an object model (the usual approach, which risks silently dropping/altering OOXML details a model doesn't fully capture); instead flattens just the plain text (extract_flat_text, walking document.xml with quick-xml's streaming reader) while recording each <w:t> run's exact byte range in the raw XML, then splices edits directly into the original bytes at that exact range (apply_edits). Every byte outside a targeted run is guaranteed untouched by construction. Key correctness subtlety handled: never slices raw XML mid-entity (a run's encoded text like "Smith &amp; Sons" has a different byte length than its decoded form "Smith & Sons") -- instead always replaces a touched run's entire raw content wholesale after a decode-splice-reencode round trip in decoded space, which makes entity corruption impossible by construction rather than by care. Refuses (does not guess at) an edit spanning more than one run, matching the project's established "flag conservatively" philosophy. 20 tests total: 18 unit tests plus 2 integration tests proving the surgical claim against a real document (Atherton Storage's blank lease template -- no tenant PII, committed as tests/fixtures/ following the same precedent as the dedup tool's own real-facility-data fixtures) -- verified every other zip entry is byte-identical after an edit, and everything in document.xml outside the one targeted run's text is byte-identical too. Also manually verified via Word COM that the edited output opens cleanly in real Word with no repair/corruption prompt. cargo fmt/clippy/test all clean. Committed as f590801 (crate) + 569e895 (follow-up fixing a stray Dropbox metadata sidecar file that leaked into the fixture commit via the Windows/Dropbox copy). Not yet wired into any pipeline or endpoint -- built and proven standalone, same sequencing as detect_candidates.
